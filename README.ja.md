# Personal Agent Lab

[English](README.md) | [日本語](README.ja.md)

新規設計のパーソナルAIアシスタントを開発する公開リポジトリです。次の実現を目指しています。

- 自然な会話
- 永続的な記憶と参照
- ユーザーに内部タスクの管理を求めない作業完了
- Primary/Responder と Expert/Executor の分担
- 証拠に基づく完了判定と、中断・再起動後の継続

**Stable-0はD-019の機能優先の定義で完了**しています。版は `stable-0` で、[完了証拠と制約](evidence/final/stable0/README.md) を参照できます。そのリリースでは必須受入20項目と最終66テストのPASSが記録され、親Issue #1はクローズされています。


## 決定的テスト

```sh
python3 -m unittest discover -s tests -v
```

正本ストアはホスト側の [pal/store.py](pal/store.py) にあり、Executorの権限には含めません。下書きはサイズ上限付きSQLite BLOBとして保存し、ホストが読み戻してreceiptを検証します。ループバックUIの既定はmockです。過去の公式実モデル機能と本人評価は [Stable-0監査](evidence/final/stable0/audit.json) に記録されています。このブランチのリリース状態と完了記録は [STATE.md](STATE.md) を参照してください。

## ローカル会話と状態確認

```sh
python3 -m pal.server --db runtime/pal.db --port 8765
```

<http://127.0.0.1:8765/> を開きます。通常の会話・記憶依頼はGoalを作りません。mockでは `Make a draft …, do not send` でローカル下書きを作り、`stop that`、`pause that`、`resume that`、`correct that: …`、`answer: …`、`forget that` で現在の作業・文脈を操作します。Inspectは読み取り専用で、Goal、Attempt、固定基準、receipt、拒否結果、エラーを表示します。送信・シェル・リモート書込みの機能はありません。Browser Session receiptには受理したIDだけが入り、本文は入りません。検証証拠が必要なら、セッションを閉じる前にコピーしてください。スクリプトのreceiptを本人評価として扱いません。

## 公式実モデルのsmoke検査

[過去のsmokeスクリプト](scripts/live_smoke.py) は利用証明ファイルと出力フォルダを位置引数で受け取り、`--help` は実装していません。通常の導入手順には含めません。明示的に許可された実モデル検査の直前に、既存のログイン済み公式Proアカウント、利用枠、credits OFF、auto-reload OFFを確認します。利用証明は15分で期限切れとなり、native認証を再確認します。証明の捏造や有料fallbackの有効化は禁止です。成功済みの証明は過去のsmoke記録であり、新しいモデル呼出しへの継続許可ではありません。既定UIと任意の連続観察はnative呼出しを行いません。

## 実モデルUIの明示的な有限起動

制御担当が既存の公式Proアカウント、利用枠、credits OFF、auto-reload OFFを実際に確認した後、メタデータだけの利用証明ファイルを作れます。キーは `verified_at`（現在のUnix秒）、`no_extra_charge`（true）、`route`（official_claude_pro）の3つだけです。資格情報・tokenは入れません。そのうえで明示的に起動します。

```sh
python3 -m pal.server --db runtime/functional.db --port 58500 --provider official_claude_pro --access-proof runtime/fresh-proof.json --native-call-limit 16
```

起動時の証明は15分以内で、このcheckoutで一度だけ消費されます。新規呼出しの受付期限も既定では壁時計・経過時計の両方で15分です。明示的に許可された長い試用では `--native-session-seconds 8100` により、最新確認から2時間15分まで受付できます（整数1〜8100）。D032では準備完了の通知時に2時間以上を残すため、この余裕を使います。呼出し予算は増えません。起動失敗でも有効な証明は消費されます。`runtime/native-proof-use` の使用済みマーカーを保持してください。証明のコピー、JSONの書式変更、セッション時間変更で再使用できません。これはローカル運用者の保護であり、暗号学的証明やアカウント全体の上限ではありません。信頼された運用者はローカルメタデータの偽造・削除や別checkoutの使用ができてしまいます。

会話・作業共通のproviderは、最大16回の生成呼出しを予約します（設定可能範囲1〜32）。PrimaryとExpertが枠を共有し、1回の下書き依頼が複数枠を使う場合があります。失敗した呼出しも1枠を消費します。制限対象はホストの呼出しであり、観測できないCLI内のHTTP再試行やtoken更新は含めません。各認証段階は10秒以内、認証後にも受付期限を再確認し、生成は120秒以内です。受付済みの処理は、既存の監督プロセス終了猶予を含め、表示期限後まで続く場合があります。UIはモード、残り予算、ローカルの絶対受付期限、固定の失敗コードを表示します。スリープ中も壁時計の期限は進みます。期限切れ・枠超過・認証失敗を表示し、mockへの無通知切替、更新、再試行は行いません。新しく許可する呼出しには最新確認と明示的な再起動が必要です。時間だけを延長するときも実際の残り回数を `--native-call-limit` に引き継ぎ、残り0を16回へのリセット許可にしません。失敗した作業には新しい依頼が必要です。追加利用なしの設定は証明発行時に確認し、各呼出しの認証だけでは独立に再確認しません。

中止・一時停止は作業結果の適用を防ぎ、無関係な会話を終了しません。受付済み呼出しは中止後にも枠を消費する場合があります。ホスト終了・異常終了時は監督対象の認証・モデルプロセスを終了します。固定機能シナリオはACCEPTANCE.mdにあります。内容検査・実provider出力と、本人による一度の有用性評価は別の証拠です。

## Stable-1の使い方と現在の制約

実モデルを明示して起動した画面では、日本語・英語で自然に依頼できます。会話の文脈を使ってローカル下書きを作り、足りない情報を質問した場合はそのまま回答してください。対象が複数あれば、どの作業かを選んでから訂正します。作業中・一時停止中は会話か作業欄の「訂正」「中止」を使えます。完了済みの本文を変更したいときは、変更点を添えて「新しい下書き」を依頼します。成果物は「下書きを開く」で表示し、送信前には本人が必要な内容を確認します。外部送信・公開・予約などはできません。

残して使いたい情報は「覚えておいて」と伝えられます。「AI参照を停止」は今後のAIへの参照を止める操作で、保存済み履歴の物理削除ではありません。文脈は直近30記録・先頭20記憶に制限されます。すべての過去の会話を覚えているとは限りません。

下書きの言い回しや補足には不完全さがあります。訂正と利用時の指摘は後の開発に使えますが、自動学習・自動モデル更新・経験から必ず改善する機構は未実装です。追加の文章品質試験より初期版の利用を優先しています。権限・費用・誤対象の変更・参照停止・復旧の保護は維持します。

実モデルの検証記録は既存の公式Claude/Opus経路によるものです。Qwen3.8-27Bは能力基準の参照であり、PALでの実動作は未検証です。画像・音声入力は将来版の設計資料があり、現行実装にはありません。公式実モデルの利用は新鮮な既存契約確認後の有限セッションです。既定は16呼出し以内・15分の利用証明で、1依頼がPrimaryとExpertの2呼出しを使う場合があります。期限切れ・上限到達時に有料経路へ切り替えず停止し、保存済み結果は閲覧できます。再開には運用担当が現在の費用設定を確認して、許可された新しいセッションを明示的に起動する必要があります。常時自律実行・自動監視や停止済みスケジュールは有効化していません。
