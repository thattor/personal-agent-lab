## Verified sound against actual code

- **Pause mechanics support the plan.** `pause` calls `_fence` (fences the running attempt + bumps epoch) then sets `paused` (store.py:421-423). Paused goals remain eligible targets — `_natural_control` excludes only `completed`/`cancelled` (and `unknown` for correct). Two paused drafts → cue-less natural control → `selection_required` → rendered buttons (app.js `selectWork` POSTs `{action:select, selection_id, source_key, target_id}`). Because pause bumps epoch and no claims occur while paused, the snapshot stays valid — the apply path is deterministic.
- **Only intended target mutates** is checkable: selected correct → revision+1, same `acceptance_id` (criteria reuse), `sources=[control record_id]`, spec = stored proposal text verbatim; unselected goal byte-identical.
- **Late-result fencing is provable**: cancel while `running` → `_active()` fails for the fenced attempt → `rejections` row `'stale artifact'`, no receipt.
- **Budget is small**: only conversation replies and `DRAFT` executions consume slots; classification, controls, selections, and canned replies make zero provider calls.
- **Provenance precedent exists** (F0-05 manifest-bound reconstruction) and is adequate here.

## Corrections needed

1. **Suite-global call budget is not enforced by "max32".** The limit is per-proof/per-host (`NativeClaude(max_calls)`). Separate fresh DBs mean ≥4 host starts → 4 one-use proofs → up to 4×limit legal calls. If the intent is a global ≤32, freeze per-host limits summing ≤32 (estimated actual usage: A=1, B=1, C=2, flow≈4–6 ⇒ ~9 calls; e.g., 4/4/4/16) and record `calls_remaining`/`last_error` per host. Otherwise explicitly disclose the bound is per-host.

2. **N1-05 output channel:** the Executor can only return draft text — there is no question/clarification channel (`waiting_input` exists in the result contract but `ProviderExecutor` never emits it). A "conversational question" can therefore only appear as question-text *inside the artifact*. The frozen rubric must classify artifact bytes into {placeholder draft, omitted-field draft, question-text, contains-invention} and pre-decide whether a question-artifact satisfies the row — otherwise the first ambiguous output triggers ad-hoc judgment. Also freeze per-probe supplied-fact whitelists and the 2-sentence counting rule; invention = any concrete particular outside the whitelist, judged on bytes.

3. **Ambiguous-correction payload contains "Cedar"** — the intended target's name. Cue extraction is prefix-only and the payload is verbatim spec (D-024), so it stays ambiguous — but the payload naming a target weakens the "genuinely ambiguous" claim and invites an N1-07 "unnecessary question" mark. Recommend a target-neutral payload (e.g., `その下書きを訂正して: もっと簡潔に、日本語で2文にしてください。`) or explicitly document the adopted payload-is-verbatim semantics.

4. **Pause ordering is load-bearing.** `pause that`/`一時停止して` binds to `_latest_goal()` only. The script must interleave create→pause→create→pause (the fixture's "after each request" is correct — keep it) and verify actual `paused` state before proceeding. If a draft completes before its pause lands (real provider latency is seconds — low but nonzero probability), the goal is ineligible → ambiguity collapses → record `not_run`/`unverified` per race_policy and retry on a fresh DB; never count a completed goal as paused.

5. **Unfinished-cancel needs an admitted call.** Single running slot: Maple stays `queued` while Cedar's corrected attempt runs. Cancel-while-queued proves cancel but not fencing. Poll `/api/state` until Maple is `running`, then send `Mapleの下書きを止めて`. Bounded wait for the `'stale artifact'` rejection row; if the subprocess outlives the window or the host stops first, fencing is unverified — do not claim it.

6. **Proof window vs. flow duration.** `proof.check()` runs on every call admission; expiry is 900s wall+monotonic. Each host's scripted run — including the fencing wait (generation up to ~128s) — must fit inside its proof's window. Issue each proof immediately before launch; mid-flow expiry yields honest visible `proof_expired` failures and a fresh check+proof on retry (executor errors fail goals terminally — no burn-loop, but each admitted call still consumes its slot).

7. **Context isolation is required, and expensive.** Shared DBs would put earlier request/event records into later prompts, turning "invention" into "grounded-but-wrong" → ambiguous rubric verdicts. Confirm 4 owned DBs/hosts (A, B, C, flow) on distinct loopback ports → 4 proofs + 4 fresh operator checks (plus ~1 spare for a burned startup). `fresh_context: []` demands this.

8. **Provenance wording.** "Exact reconstructed prompt" = re-executing the deterministic format+sanitize over canonical manifest-bound bytes — byte-exact and provable, but not a raw stdin capture, and raw pre-sanitize stdout is never persisted (artifact stores sanitized bytes). Declare both, per F0-05 precedent. True wire capture would be a provider-boundary change → design gate; not required for this contract.

## Decision boundary to pre-commit

If a probe fails with invented particulars, the evidence-first fix is a minimal system-prompt generalization ("never invent missing particulars; use placeholders") — treat this as implementation under the adopted N1-05 gate and record it in DECISIONS. But if outputs show the model needs to *ask* for missing content operationally (executor-emitted `waiting_input`, clarification flow), that is Stable-1.1 scope — stop and consult Opus + human per D-021/D-022. State this boundary now so a failure doesn't force an ad-hoc authority call.
