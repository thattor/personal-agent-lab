def _object(pairs):

    for key, value in pairs:
        if key in result:
            raise ValueError('duplicate Primary field')

        raise ValueError('invalid Primary text') from exc

        raise ValueError('oversized Primary text')

# Verdict

**Make one targeted change to the Primary prompt only. Leave the native system prompt unchanged.** Candidate `1a14de9` stays **FAIL**, and nothing here marks acceptance PASS.

**Is recurrence a sufficient reason?** Yes, but not because two misses are statistically meaningful. They aren't: R02 and R10 are the same request in two languages, run on one frozen product. The fix is justified for two other reasons:
- `1a14de9` already fails the frozen fixed40 gate (15/16 can no longer be reached), so some product change is needed anyway.
- Both misses follow from one ambiguous sentence in the contract, so this is a wording defect, not a random failure.

**Root cause.** The current prompt says "Ask only missing facts that materially change the result." A recipient name *does* change the result. Read literally, the model is following the contract when it asks. The other trigger, "a generic/fictional draft is requested," gives no permission when the user didn't say "generic." Meetings work today because nothing in a meeting request suggests personalization. Thank-you notes do. The problem is the threshold for asking, not a missing rule about thank-you notes.

**Why not change the native system prompt?**
- It contains nothing that tells the model to ask questions about drafts. Its thank-you sentence governs content and is already correct. Its "personal project" clarification sentence is scoped to projects, not drafts.
- The Expert also uses the native prompt. Editing it would change Expert generation everywhere, invalidate more of the existing absence evidence, and widen re-verification for no identified benefit.
- If the Primary-only change still misses on the new hash, that is a separate finding and a separate change. Don't pre-empt it.

**Safe miss vs. unacceptable false positive.** Both current misses were `none` with no effect, so the host stayed safe; they are usability failures. This change deliberately trades those safe misses for false-positive risk:
- delegating on hypothetical, quoted or negated requests;
- delegating when accept/decline or the actual purpose is unknown;
- the Expert inventing details once less context reaches it.

Zero false positives therefore stays the gate that cannot be bent. Delegation recall comes second.

3. **"Explicit blanks" may push the model to insert blanks everywhere.** R10's gold asks for useful general thanks. Put blank placeholders only where a blank template was explicitly requested (the existing sentence already covers this).
