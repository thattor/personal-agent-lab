**Design assessment: PARALLEL-SCOPE-1 §C (read-only, supplied snapshot only)**

**1. EXE02-request/1 (`pal/github_read_request_v5.py`): consistent with scope**
- **Pure module.** It imports only `dataclasses` and `urllib.parse.quote` (`:16-17`). It does no I/O, mints no IDs and has no try/except.
- **Validation matches the scope:**
  - Capability allowlist (`:109`).
  - Exact plain dict with the exact key set per capability (`:116-121`).
  - Repository: wrong type gives invalid_input, a foreign repository gives denied (`:124-127`).
  - Issue number is a strict int, at least 1, at most 63 bits (`:131`).
  - Path rejects empty, `.` and `..` segments, backslash, C0/DEL and surrogates (`:71-86`).
  - Ref must be lowercase 40-hex (`:89-94`).
  - Each path segment is quoted with `quote(safe="")`, keeping the `/` separators (`:141-144`).
  - Bounds are 1..30 seconds and 1..1048576 bytes; invalid values give invalid_input, values above the maximum give limit (`:146-153`).
  - argv is a fixed 7-element tuple (`:155`).
- **Contract fit.** The values match the C07 initial limits and use only the C07 Result codes.
- **Errors.** Messages are fixed constants (`:30-40`) and `args=(message,)` (`:52`), so raw input is never echoed.
- **Documented residual (`:58-63`).** A directly constructed `ReadRequest(...)` is not validated. The future EXE01 executor must accept only `prepare_read` output.

**3. ART01-content/1 (`pal/artifact_content_v5.py`): consistent with scope**
- Strict str type and media checks (`:59-66`).
- UTF-8 encoding raises outside the except block, so no exception is chained (`:67-73`).
- Inclusive 1048576-byte limit (`:74-75`).

- Result is a frozen, slotted dataclass (`:42-50`); content and data are hidden from repr (`:46`, `:48`).
- It creates no Ref, ID, source check or DB access.
