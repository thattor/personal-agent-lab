# P-001 v2 draft — 小さな到達点を積み上げる開発計画

Status: DRAFT / NOT ADOPTED. P001 v1を保持し、本人の改訂指示とP002採用を反映したレビュー用案。Opusとの協議後、固定した提案版を人間判断へ渡す。現在のStable-1開発許可を変更しない。

## 全体ゴールと最初の完成版

全体の目的は、会話の文脈を保持し、自然な依頼を受け、許可された可逆な準備を進め、検証結果と必要な本人判断を返す個人用アシスタント。全体ゴールを縮めず、小さな版で実際に使って次の追加を決める。

最初の完成版候補は、本人が始めたローカル会話の中で、自然な依頼→既に渡された会話・記憶を使う→不可欠な情報だけ聞く→同じ下書きを続ける→開く→必要なら訂正／中止、を成立させるStable-1。新しい会話横断検索と、下書き以外のローカル準備拡張は最初の完成版の必須外候補。既存の記憶・参照停止・復旧・費用境界は残す。最初の完成版を全体ゴール達成と呼ばない。

## 小さい作業単位と確認ポイント

| 単位 | できることの例 | 完成条件 | 難所・対象外 |
|---|---|---|---|
| A 自然な依頼 | 「短い招待文の下書きを作って」 | 固定した依頼／雑談／保留で不要な作業が生まれず、本人の実UIで下書きを開ける | 言語のあらゆる言い方は保証しない。既存Issue3の証拠は保持 |
| B 対象を選んで訂正・中止 | 2件あるとき、選んだ下書きだけ夕食向けに直す／中止する | 選んだ作業だけ変わる。古い選択と遅い結果を拒否。実UIで本人確認 | 文章への注釈機能を追加する意味ではない。既存Issue4の保護を残す |
| C 既にある情報を使う | 日時を会話で伝えた後、招待文を依頼 | 利用可能な日時を使い、再質問や創作をしない固定実例 | 今の bounded context のみ。新検索／新権限なし |
| D 足りない情報を一度まとめて聞く | 日時が不可欠だがない場合に聞き、回答後に同じ依頼を続ける | 質問IDと作業が結び付き、回答・重複・訂正・参照停止・再起動でも誤再開しない | 実装上は質問と回答の保存・競合が難所。本人に内部管理を要求しない |
| E 解決しない場合を正直に返す | 「日時未定のテンプレートで」／質問後も情報不足 | 未完成表示、捏造なし、完了扱いなし、上限内で止まる | 無限質問／追加費用／勝手な生成回数増加なし |
| F 最初の完成版を評価 | A〜Eの固定した実利用例を通して使う | 現必須N1各行PASS、本人の有用性再評価、最終フルテスト、版／制約／Issue監査 | テストやレビューのみで本人評価を代行しない |

A/Bは既存証拠付き実装を再利用して評価し、再開発しない。C/D/Eは採用済みP002を小さい実装・検証単位に分ける。同じStable-1 milestoneのIssue内で、各単位のゴール・証拠・達成評価を記録する。単位PASSの積み上げだけでFを自動PASSにしない。

## その後の候補

最初の版を使ったチェックポイントで、必要性と実例が分かった機能だけ次の小さいmilestone候補にする。会話横断の記憶は「別の会話で指定した1件を根拠付きで呼び戻す」から、ローカル準備拡張は「本人が依頼した1種類の可逆な成果物」から提案する。具体的な範囲・固定受入・費用／権限をOpusと協議し、本人が確定するまでは未承認。これらを恒久的に削除したり、全体ゴールに必要な文脈保持を完了扱いにはしない。

公開検索、時間起動、自発提案、Dreaming、vector DB、多Expert、ローカル推論、外部送信は自動で追加しない。停止済み定期実行は再開しない。

## Project → milestone → issue の評価

各green作業単位でIssueの目的・証拠・残り・次の操作を評価し、Issue出口でmilestoneへの寄与、milestone出口で本人の価値と全体への寄与を確認する。計画変更は根拠→Opus合意→版付き案→人間判断→正本／GitHub反映。待ちは依存作業だけ。全体ゴールIssue6は、後から採用した必要範囲と統合利用価値が実証されるまで閉じない。
