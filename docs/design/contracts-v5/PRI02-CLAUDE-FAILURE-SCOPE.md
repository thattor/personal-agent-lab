# PRI02-CLAUDE-FAILURE/1 — prospective private failure observations (PROPOSED)

Root proposal for milestone design review, not yet a source assignment or actual
provider allowance. Current C094 remains consumed UNKNOWN/active held. This adds
no recovery/release/retirement API, attempt root or qualification. No old case is
updated retrospectively; no original ending is synthesized. Model prose quality
is not tested. CO is optional; existing authorized first-party Opus5.5 consultation
is design advice only.

## Problem and minimum boundary

Current tools/native_claude_text_v5.py suppresses error-cleanup exceptions and
replaces the original activated exception with a generic RuntimeError. Original
C094 therefore has no durable detailed exception or cleanup outcome. The usage
schema rejection is reproduced, but a separate original cleanup failure remains
unexcluded. Prospective observation should distinguish these events without
changing transport acceptance or falsely claiming remote cessation.

Limit source to tools/native_claude_text_v5.py. Preserve existing max1/active,
preflight, exact model/request/pin/argv, on_enter/Popen order, bounded streams,
owned WNOWAIT/kill/wait cleanup, strict ending/capture and original exception
classes at the public boundary. No other source or current test/fixture bytes
may change. Root owns the contract/canon; isolated tests precede separate source
and an independent review. Source changes invalidate the old pin.

After an activated failure, attempt cleanup exactly once as currently required;
save an optional bounded private failure.json in that newly owned call directory.
Use existing exclusive0600/no-follow/fsync writing. Best-effort diagnostic failure
must neither replace the original control result nor release active. Success or
pre-activation refusal adds no diagnostic. Never overwrite an existing file.

Proposed closed fields: version NATIVE-CLAUDE-FAILURE/1, request_sha256,
profile_sha256, attempt_ref, phase, primary_error, cleanup_status, cleanup_error,
observed_stdout_eof, observed_stderr_eof, observed_exit_code,
ending_write_completed, capture_write_completed. Canonical UTF8 bytes <=4096.
Request/profile/attempt bind the current activated invocation, not a retrospective
case. Do not serialize request/output/auth/environment or an exception message.

phase is a finite wrapper phase: durable_admission, buffer, entering_hook, spawn,
capture_streams, pump, finish, validate, owned_wait, save_ending, save_capture,
release. Track the phase directly, not by parsing exception text. Each error is a
closed kind/errno/sites object. Kind is from fixed standard exception classes or
OtherError; errno is integer or null. At most8 sites contain only a fixed allowed
repository-relative source file and a positive source line. No absolute path,
function/locals/message/repr or private value appears. primary_error and
cleanup_error remain separate; cleanup_error is null unless cleanup failed.

cleanup_status is not_attempted/succeeded/failed. A succeeded cleanup reports
local execution only; it is not remote cessation, accepted ending or recovery.
EOF/exit fields are null unless _pump actually returned its original observations;
do not alter _pump merely to collect more observations. EOF true is retained only
when observed; integer exit only when observed. A failed pump records null even
if some observations might have happened internally but were not returned.
ending/capture write flags mean their durable write returned successfully; false
does not prove that a partially written path is absent. Diagnostics are never
consumed by NativeReturned or a release/qualification decision.

## Fixed functional cases and completion

Freeze8 methods before the source change: feed/finish failure versus successful
cleanup and active retention; original failure versus cleanup EPERM; original
KeyboardInterrupt/SystemExit propagation with one cleanup; diagnostic disk refusal
without altered UNKNOWN; unobserved versus returned EOF/exit distinction; unchanged
normal success/preactive typed refusal; private canary exclusion/4096 bound/0600/
exclusive existing-file retention; unchanged old UNKNOWN inventories.

Use only typed synthetic frames and inert owned child fixtures or narrow mocks.
No actual CLI/model/auth/service/fee or old-call operation. Retain original REDs,
commits/diffs/test commands/counts/exits/log hashes and remaining limits. Separate
source review and Root full suite precede local source acceptance. Real qualification
and any further MAX1/disposition need a separate explicit current decision; this
proposal cannot revise D065's no-second-entry/no-rotation boundary.

## Unresolved old-UNKNOWN decision

Current public APIs and saved evidence provide no way to recover C094's original
owned EOF/wait/ending. This does not prove no original simultaneous record exists
elsewhere. Preserve all old files and active. Human may choose continued hold, or
explicitly allow a distinct finite future qualification while retaining old UNKNOWN
without asserting ending/release or adopting its text. The latter revises the
current boundary and requires a concrete separate operator/source/budget/account
freeze. It is a proposed human decision, not permission inferred from this file.
