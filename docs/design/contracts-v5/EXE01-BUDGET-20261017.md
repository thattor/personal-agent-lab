Tracked requirement: [Issue #22](https://github.com/thattor/personal-agent-lab/issues/22).

## Scope implemented

- `TaskStore.reserve_budget({key, work_ref, kind:"operation"})` now
  reserves one operation quota against **both** the existing per-Goal
  `Grant.limits.max_operations` and the finite host
  `host_limits.max_operations`. The reservation is associated with
  the active lease and strict current WorkRef.
- C15 same-key replay retains the first receipt; conflicting inputs fail
  closed. `consume({reservation_id,call_or_operation_id})` binds once,
  rejecting a distinct operation ID.
- The new `v5_tsk_host(kind='operation')` row retains consumed usage
  across store reinitialization. Corrupt negative/inverted/noninteger
  operation counts fail without new consumption.
- Nonread `claim` admission checks step/model ceilings only; an exhausted
  operation limit cannot block a Goal that does not invoke EXE.
- Zero-operation request is now explicitly `limit` rather than the
  historical not-implemented `unavailable`. No grants are expanded by
  this change. Existing model and step budget receipts remain unchanged.

## What this does NOT implement

No C07 `prepare/execute/get/recover` operation ledger; no
step/action capability binding, source registration or provenance,
EXE02 invocation, real GitHub read, content/receipt storage, recovery
proof, remote child cessation proof, native model, user evaluation, or
release. `Operation` remains an unimplemented public contract.

The previously retained untracked `pal/operations_v5.py` and its
tests in the original machine's isolated worktree were **not accessed,
overwritten, cleaned or adopted**. Original unknown calls remain held.
