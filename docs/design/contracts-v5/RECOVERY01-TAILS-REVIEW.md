## Safe dispositions after restart

A startup lock must cover the trusted mock callable's actual lifetime, not just database opening or startup reconciliation. Existing TSK refuses a different runner's active lease. A new runner ID must not become permission to redispatch an old call. Acquiring the proposed lock can establish absence only for the scoped cooperative in-process mock execution; it cannot establish termination of an escaped child/provider or resolve prior unknown CO/AGY calls.

1. **Finished report/compose/ask, committed reply lost:** preserve persisted Step/results/events/budgets. Finish/ask replay is a historical receipt; inspect latest work separately. Never duplicate a report event, ART body, question or Expert callback. An answered or superseded old question is not reopened because lookup returns its original waiting receipt. Failed/malformed lookup is uncertainty, not absence.
2. **Started report with valid ended call:** its summary Action is durable. Current same-runtime exact finish can commit once, with original authority and source checks. Once startup recovery invalidates epoch/releases the old lease, existing finish cannot adopt it: `_authority` plus exact Step WorkRef checks reject (`tasks_v5.py:628–635`). A future recovery API could explicitly persist a current binding/event after eligibility checks; absent that API, defer or abandon as unfixed observation, without inventing report success.
3. **Started ask with valid ended call:** reconstruct exact request from persisted Action and original WorkRef. First query its C04 key. Saved receipt means the atomic ask already completed; reconcile latest state, do not ask/finish again. `not_found` alone does not authorize fresh old-epoch ask after recovery; changed epoch/revision/control fences still apply. Any supported re-adoption must retain atomic question/Step/event/lease semantics and historical identity.
4. **ART saved, compose Step still started:** query C08 key, validate receipt, then use actual ART metadata and producing-call provenance. Body existence is separate from TSK attachment. Existing `_finish_compose` is current-authority binding; old-epoch attach has no public recovery seam. C13 explicitly permits same-revision old-epoch ART recovery adoption after current purpose/source/freshness checks into a new binding; that requirement is not implemented by existing finish. The first startup scope must either implement that bounded seam or explicitly defer these tails. Do not call save again with a fresh key and do not classify abandoned Step as proof that no artifact exists.
5. **ART attachment committed, reply lost:** current persisted set and finished Step are canonical. Historical finish replay returns original binding only; no second attachment/event. If control/source-stop subsequently fenced the work, retained artifact is history, not new model input. No need to repeat save or Expert inference.
6. **VER saved but completion not committed:** retrieve original key if the ordered set is known; checks remain historical facts. Before any fresh complete, `get_verification`/transactional `inspect` must establish current typed authority; TSK itself compares epoch, whole ordered set, Condition IDs and full source union, then gates sources and ended Steps/calls. Old-epoch VER must not complete new epoch. New epoch requires new current verification; replaying old verify cannot refresh it. If completion already committed, canonical C10 replay is useful history; latest state inspection remains separate.
7. **Returned call without Step or admitted/unknown call:** no durable Action is available in the first case; do not fabricate it or consume another model budget as a replay. Admitted means not-entered/running/ended-but-unsaved remain indistinguishable. Initial ended-only cleanup must retain admitted/unknown/corrupt cases occupied, as preparation already proposes. No label conversion to raised/not_entered from process absence.

## Epoch, revision and source rules

Same-revision epoch drift invalidates fresh host result adoption; C10 human controls tolerate epoch, but complete/save/ask/finish do not. C13's explicit old-epoch recovery adoption is a distinct host operation, not weakened existing `_authority`. Across revisions, no old Step/ART/question transfer into the replacement: preserve old history, use latest cancel/pause/drain intent for slot cleanup, never let old failure fail replacement (CHANGE01). Replaying original keys may succeed despite fresh old-revision authority being stale.

Required stopped sources prohibit fresh processing/adoption. Optional stopping is eligibility-specific: an unused optional record can be excluded, but every producing call input is conservative dependency of a compose output, even when Action selected fewer refs. Thus a stopped unselected call input still blocks artifact/derived Step re-entry. Reconciliation must use persisted full call/source union, not only compose.action.source_refs. ART get_by_key keeps raw receipt available; ART inspect/read with processing purpose gates dependencies. VER `_current_status` distinguishes legitimate stale/source-stop invalidation from corrupt/unavailable owner evidence (`verification_v5.py:396–437`); unavailable must not become a semantic unmet/safe-discard conclusion.

Add fresh-process cases: saved C08 receipt + started Step, save commit lost reply, finished attachment lost reply, saved VER with changed epoch/set, atomic ask committed while runner reply vanished, change/pause/cancel/stop before reconciliation, and unknown/malformed receipt lookup. Assert one body/set/question/event, unchanged consumed budgets, zero old callback dispatch and independent latest-state inspection. Query keys before changing epoch where feasible, but never use a receipt to bypass current authority; reconciliation, current source checks and state/lease write must share one TSK transaction or explicitly fail/defer.

The blocker to claiming **full C13 recovery** is absent explicit recovery adoption/receipt discovery: no TaskStore.recover; no safe old-epoch Step/ART attach API; VER key requires saved ordered set and is not a Step-derived key; no public TSK finish/complete receipt getter. A bounded ended-orphan settlement implementation can still be useful if these unresolved tails are explicitly deferred and finished history is preserved. Root must freeze that scope distinction before source/tests. No migration, semantic authority, model retry or EXE activation is proposed.
