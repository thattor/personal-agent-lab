## 2. 流れに沿った照合

- 新規依頼：UI→C05原文→C02候補＋C06/C11文脈→C01意図→C03正式受付→C13 claim→C15モデル→C12行動。原文と候補を参照だけ渡して本文を読めない欠落は修正済み。
- 調査と成果：C12 operate→C07 prepare/execute/get→C11原本文→C12 compose→C08→C13成果物結合→C09→C10 complete→C14。モデルの成功文だけで完了する経路を持たない。
- 質問：C12 ask→C04質問/待機/step確定→C14表示→C05回答原文→C01質問選択→C10 answer→queued→C13再開。同じGoalを保つ。
- 停止/変更：ボタン又はC01→C10→新しい手の開始を拒否→既存呼出し回収→C13 release。無効化されたepochからも自分のleaseだけ解放できるよう修正済み。
- 記憶：C05保存/要約→C06検索→C11原文。訂正・参照停止はMEMからTSKへ利用出典経由で通知し、以後のモデル入力・成果採用を止める。
- 復旧：単一起動確認→EXEの所有呼出し確認→TSKの未確定step照合→保存済み結果回収→現状態に応じて再開。実行済みと不明な実行は区別する。
- 通知：状態変更・質問・雑談・記憶操作ごとにC14へ保存し、切断後もcursorから取得する。Goalのない会話でも表示可能に修正済み。

## 4. 実装後の検証順序と合格の意味

| 段階 | 検証対象 | 方法 | この段階で言えること |
|---|---|---|---|
| D 設計照合 | 契約の送り手/受け手・意味・状態 | 本文と上の接続表/シーケンス照合 | 実装担当間で共有すべき約束が記載されている |
| U 単体 | モジュールの担当機能 | 入力例・境界値・必要な失敗例。外部依存はfake | その部品が期待する結果を返す |
| C 契約試験 | 公開入出力と副作用 | 同じ契約例を提供側fakeと実物へ適用 | fakeだけで成立する独自仕様を防ぐ |
| I 接続 | 実モジュール同士 | producer出力を無加工でconsumerへ。DBと参照を読戻す | 実装した接続が合い、状態/保存がつながる |
| F 故障・競合 | 停止/変更/再起動 | 決めた境界で中断・順序制御。実外部への破壊操作は不要 | 二重操作や古い結果の採用を防ぐ |
| E 全体結合 | UIから結果表示まで | 最初は制御可能なprovider、その後実モデル/実接続で確認 | 全体経路と実際の接続能力を別々に確認 |
| H 本人の実用評価 | 説明/指示/進捗管理の負担 | 一連の仕事を本人が利用 | 実用価値を本人が評価した範囲で確認 |

U/C/I/Fは各担当・小マイルストーンで並行して実施できる。EはINT-03の最初の一本道から始め、最後にINT-08で全経路を結合する。全機能完成まで接続を待たない。Hに技術的な模擬入力の選択や文体の微調整を持ち込まない。

## 5. 全体を結合した状態の検証項目

| ID | シナリオ | 必要な証拠 | 合格条件 |
|---|---|---|---|
| E2E-01 | 自然な依頼→指定情報取得→成果物→画面 | 元依頼/Goal/操作receipt/取得本文/成果物/判定/画面 | 実際に取得した情報と保存成果を同じ仕事として辿れる |
| E2E-02 | 過去の情報を使う依頼 | 原記録/関連要約/推論へ渡した参照 | 背景を手貼りせず有効な記録を利用。見つからない時は不明とする |
| E2E-03 | 必須不足を質問→回答 | question ID/原回答/再開状態 | 回答後に同じ仕事が進み、無関係な仕事を変えない |
| E2E-04 | 実行中の停止→回答/追加発言→再開 | 受付時刻/操作記録/状態/途中成果 | 停止後に新操作を始めず、再開後に保存状態を使う |
| E2E-05 | 内容変更/中止 | revision/epoch/旧結果/画面 | 変更前結果を現行成果にせず、中止を解除しない |
| E2E-06 | 実行中のクラッシュ・再起動 | 操作回数/保存key/復旧状態 | 確定済み操作を重ねず、不明を成功扱いしない |
| E2E-07 | 記憶訂正/参照停止 | 派生note/利用出典/後続モデル入力 | 以後の参照と結果採用に訂正/停止が反映される |
| E2E-08 | 接続不能/モデル不能/上限到達 | エラー/予算/途中成果/表示 | 虚偽完了・無限再試行・追加課金fallbackなし |
| E2E-09 | 作業中の別会話とUI再接続 | Turn/状態/イベントcursor | 会話と制御が扱え、既存仕事を失わず通知が重複しない |

実外部接続の成功はE2E-01で確認する。故障注入や競合の網羅は制御可能なprovider/adapterを使い、実接続試験と区別する。実モデルの言葉だけで操作成功にしない。毎回全E2Eを繰り返さず、変更箇所と依存経路を検証し、統合節目で必要な全体回帰を実施する。
